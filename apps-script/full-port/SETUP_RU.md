# Полный перенос Job Automation в Jmail: закрытый пилот

В этой папке находится конфигурируемый перенос существующего Apps Script сценария Job Automation. Ветку `main` и GitHub Pages он не меняет. Перенесены оригинальные функции анализа, проверка evidence и маршрута, создание CV/Anschreiben PDF, запись по месяцам, история дублей, черновики и текущая обработка ярлыков.

## Что хранится где

- Исходники в `full-port` не содержат пользовательский API key, личное резюме, адрес, email или Google ID.
- Ключ Gemini хранится в Script Properties под `GEMINI_API_KEY`.
- Профиль хранится как JSON в `CAREER_PROFILE_JSON`.
- Данные отправителя и пороги хранятся в `JMAIL_SENDER_JSON` и `JMAIL_SETTINGS_JSON`.
- Google IDs таблицы и папки создаются функцией `setupJmail()` и сохраняются в Script Properties.

## Первичная установка

1. Открой интерфейс ветки `Jmail_mvp`. В «Мой профиль» загрузи резюме. PDF, DOCX и TXT разбираются локально в браузере; проверь найденные поля и нажми «Скачать извлечённый текст резюме». Файл остаётся у тебя.
2. Создай Apps Script проект в отдельном Gmail аккаунте, который будет использоваться для вакансий.
3. Добавь один файл `Code.gs` и скопируй содержимое [полного скрипта](./Code.gs). Включи показ файла манифеста и вставь [appsscript.json](./appsscript.json).
4. В Project Settings → Script Properties добавь `GEMINI_API_KEY`. Ключ не вставляй в код или сайт.
5. Сохрани проект и вручную запусти `setupJmail()`. Подтверди запрошенные Google разрешения. Скрипт создаст таблицу, папку и Gmail ярлыки.
6. Открой созданную таблицу, выбери меню «Job Automation» → «Настроить профиль и критерии». Загрузи TXT, заполни контакты и критерии, нажми «Подготовить профиль». В боковой панели появятся найденные факты и фрагменты резюме; проверь их и подтверди профиль. Генератор сохраняет только поля и утверждения, которые модель вернула дословно из текста резюме. Исходный текст не сохраняется в свойствах скрипта.
7. Создай Gmail фильтр, который направляет уведомления о вакансиях в ярлык `Jmail/Вакансии`.
8. На тестовых письмах вручную запусти `processJobEmails()`. Проверь таблицу, PDF, черновики, ярлыки и корзину. Только после проверки запусти `installJmailDailyTrigger()`.

Свойства `JMAIL_SETTINGS_JSON` и `JMAIL_SENDER_JSON` мастер создаёт сам. Их можно повторно изменить через боковую панель.

## Сохранённое поведение

Сценарий сохраняет действующую бизнес-логику Job Automation: порог оценки, строгий отказ дублей и неподходящих ролей, ручная проверка при недостаточных доказательствах, проверка маршрута до лимита, создание персональных PDF, строка в месячном листе, черновик отклика и отдельная обработка автоответов/рассылок.

В исходной логике некоторые письма перемещаются в корзину, неподходящие архивируются, а ручная команда очистки удаляет неподтверждённые строки и файлы. Использовать сначала только на отдельном аккаунте и тестовых письмах. Ежедневный триггер не включать до ручной проверки.

## Синтетическая проверка

Из корня репозитория выполнить:

`node apps-script/full-port/synthetic_test.mjs`
`node apps-script/full-port/integration_test.mjs`

`synthetic_test.mjs` проверяет 8 решений фильтра (порог, доказательства, тип роли, физическую нагрузку и маршрут). `integration_test.mjs` прогоняет 6 путей оркестратора: подходящая вакансия, отказ, ручная проверка, рассылка, сбой генерации документов и автоответ. Сервисы подменены синтетическими заглушками: реальные аккаунты, письма и API не используются.
