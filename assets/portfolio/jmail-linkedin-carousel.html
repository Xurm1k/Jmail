A product UX redesign

A job-search tool shouldn’t give you another job.

How I moved Jmail from “generate a script” toward “set it up, apply, and manage it.”

JMAIL · PRODUCT UX × AUTOMATION01 / 06
The beta

It could generate the script.
Then came the chores.

More screens. More copying. More setup decisions before a job seeker could get to the useful part.

1Find the right Google screen
2Move code and settings around
3Hope the pieces connect
THE USER WAS DOING THE ASSEMBLY02 / 06
The question

What if setup felt like part of the product?

This came from my own friction with the beta—not a user study I didn’t run.

Fewer handoffsClear next stepControl after setup

The goal: get from “help me sort job alerts” to a usable workspace without asking the user to assemble an app.

START WITH THE JOB TO BE DONE03 / 06
The new flow

Four steps. Then one clear Apply.

1Connect your own Google account
2Add your Gemini key
3Upload and review your CV profile
4Set job-fit and commute criteria

Apply saves settings and opens the workspace. It does not silently start an email scan.

GUIDED SETUP, USER-OWNED GOOGLE FILES04 / 06
After setup

A workspace for the work that continues.

Check emails now
Enable daily checks
Stop the schedule
Edit CV or criteria
Delete data & disconnect

The colors show intent. The page is separate from the setup wizard.

RUN · SCHEDULE · EDIT · LEAVE05 / 06
Still a pilot

Less setup.
Clearer trade-offs.

AI can be wrong. Jmail moves messages it rejects to Trash. Use a separate job-search account and check Trash during the pilot.

Google consent and a personal Gemini key still remain. Email content goes to Gemini with consent. Applications are never sent automatically.

No invented test cohort. No accuracy claim. The next step is a fresh-account walkthrough and safer recovery.

Build automation that respects the person using it.
